# 算法说明

本文说明新版求解器如何做决定、哪些结论是精确的、哪些是估计，以及这些估计怎么验证。
设计过程和被放弃的方案记录在 [`../PLAN.md`](../PLAN.md) 与 [`plan/research/`](plan/research/)。

## 1. 模型

**状态**：一题之内的状态是（候选集合 C，已知字段，挑战相符过的字段，剩余提示 h，剩余挑战 c）。

**候选追踪是精确的。** 每次揭示和挑战反馈都是目标卡的确定函数；提示随机选择哪个字段，与目标卡无关。因此贝叶斯后验恰好等于“先验权重限制在一致的候选集合上”，不需要任何近似。先验权重是每个判定组在大师决斗卡池中的张数。

**行动**：

- 提示：从尚未知道的字段中均匀随机揭示一个（消耗 1 次提示）。
- 挑战任意一张卡：得到 6 位相符掩码；边框相符时附带目标完整边框，等级相符时附带目标规则等级（消耗 1 次挑战）。六项全中即解出。

**目标**（按优先级比较）：预期解题数 → 预期首次相符项数 → 负的预期行动数。解出的题目一定是六项全中，因此第二项主要在“解不出”的情况下起作用；第三项只用于消除无意义的行动。

**跨题分解。** 题目按顺序进行，提示和挑战是全活动共用的库存。每题都从相同的先验开始，所以“解出当前题后剩余活动的价值”只取决于（剩余题数 k，剩余提示 h，剩余挑战 c），可以写成一张表 F[k][h][c]。在“目标卡独立抽取”的假设下，这个分解是精确的；按张数不放回抽取带来的先验变化在 9 题内小于 0.4%，可以忽略。

**次数发放。** 次数每天发放并累积到活动结束，等待没有代价，所以求解器按“当前可用 + 之后还会发放”的总量规划，这与按总库存规划完全等价。

## 2. 基础运算（全部精确）

| 运算 | 做法 | 本机速度（原生） |
|---|---|---|
| 反馈编码 | 每对（猜测卡，目标卡）的反馈压缩为 12 位编码，由两张 16×16 小表和四个相等比较得到，代替 8023² 的完整矩阵 | 约 3.1 ns／对 |
| 分区 | 稠密直方图 + 首次出现列表，按反馈把候选分组 | O(\|C\|) |
| 快速指标 | 由各字段的加权直方图一次算出所有 8,023 张猜测卡的直接猜中质量、各字段相符质量和信息熵上界 | 约 1 ms |
| 信息量前 K 名 | 熵的上界 H ≤ Σ H(各字段反馈) 先排序，只对可能进入前 K 名的卡做完整分区 | 前 64 名 0.5–2.4 ms（全部分区需 58–124 ms） |
| 等价行动合并 | 两张猜测卡在当前候选上产生完全相同的分区和相符奖励时只保留一张；由每个字段“能匹配到的已出现取值集合”在 O(1) 内判定 | 约 0.2 ms |

等价合并有一个细节：已被挑战相符的字段通常可以忽略，但**等级字段不能**——规则等级相同的候选，卡图等级可能不同（规则等级卡），猜测卡在这一字段上仍可能把它们分开。这个问题是被随机属性测试发现的。

## 3. 精确层（能证明时就证明）

**最后一题**（之后没有价值）：对候选集合做完整的期望最大化搜索。

- 候选不超过 64 个时，集合用 64 位掩码表示，记忆化键是无冲突的 128 位整数（集合、已知、相符、h、c）。**不包含已猜过的卡**：同一张卡再猜一次只会得到已知的反馈，严格劣于不猜，因此它不改变最优值。这正是旧版会冻结几十秒的原因。
- 资源封顶：提示 ≤ 未知字段数；挑战 ≤ \|C\| + 6 − 已相符字段数（不做无效挑战的策略不会用得更多）。只在最后一题有效，因为多余资源在那里没有价值。
- **分支定界**，使用可证明的上界：
  - P̄₁：先把剩余提示全部用掉，再挑战一次就解出的最大概率（信息不会有害，提示揭示的字段集合是均匀随机的子集）。只对“下一次挑战”成立。
  - 解题上界：c = 1 时为 P̄₁·(1 + F)，否则 P̄₁·(g(1) − g(2)) + g(2)，其中 g(j) = 1 + F(h, c − j)。
  - 行动下界：c ≥ 2 时期望行动数 ≥ 2 − P̄₁（不用提示），否则 ≥ 1。
  - 某行动的上界严格低于已找到的最佳精确值时跳过它；节点的最佳值达到节点上界时提前结束。

测量：在随机小卡池上与暴力搜索完全一致（带/不带剪枝、带/不带跨题价值共 300 组）；在 57 个真实终局上与不剪枝版本完全一致。最坏耗时（原生）：12 个候选以内 ≤ 8 ms；16 个以内有提示时 ≤ 14 ms、无提示 3 次挑战时 115 ms；20 个以内有提示时 ≤ 6 ms、无提示 3 次挑战时 365 ms（加剪枝前最坏 54 秒）。在线使用时状态预算为 3 万个节点，超出即退回下一层。

**其他题候选很少时**（≤ 7 个）：同样精确求解，但解出后的价值取自估值表 F̂，标为“题内精确 · 跨题估计”。

## 4. 离线拟合的两张表

### 4.1 跨题价值表 F̂[k][h][c]

从 k = 1 开始逐层计算：对每个（h, c）格子，用“参考 F̂[k−1] 的深度 2 搜索策略”模拟 64 个新题目，取

  F̂[k][h][c] = 平均[ 解出 × (1 + F̂[k−1][剩余 h][剩余 c]) ]

（相符项数同理）。所有格子使用同一组随机题目（公共随机数），格子之间的差别噪声很小。之后做单调修复（更多次数不会更差），并限制在 0 ≤ F̂ ≤ min(k, c)。

当前网格：k ≤ 8、h ≤ 11、c ≤ 36（9 题活动足够；超出网格的值会被截断）。拟合耗时约 290 秒（20 线程）。

从表中可以读出：边际上一次提示约相当于 1.1–1.4 次挑战，而旧版使用的固定比例是 0.61。

### 4.2 学习估值（本题还需要多少资源）

对模拟中每一个决策点，记录（候选集合的信息熵、是否还有提示），并在该题解出后记录从这一点起实际用了多少次挑战 J 和提示 E。按熵分箱（每 0.5 bit 一箱，共 28 箱）统计 P(J, E | 箱, 有无提示)；样本不足 40 个的格子依次借用“另一种有无提示”和相邻箱的数据。

搜索到达深度边界时，用它估计剩余价值：

  V̂ = Σ P(J, E) × [J ≤ c] × (1 + F̂[k][h − E][c − J])

也就是把“本题还需要多少资源”和“剩下的资源在后面几题值多少”组合起来。提示和挑战怎么取舍，由拟合出的表决定，而不是一个人为设定的比例。

当前模型：从 4 种活动设置（9/11/36、9/11/28、9/4/30、9/0/36）的 4,000 次模拟活动中收集了 139,569 个样本，拟合耗时 43 秒。只用一种提示充足的设置拟合时，“没有提示”的格子几乎没有样本，所以必须混合多种设置。

两张表一共约 57 KB，随网站一起发布（`tables/tables.bin`）。

## 5. 在线决策（每一步）

1. 若是最后一题且候选 ≤ 16 个，或其他题候选 ≤ 7 个：尝试精确层；在预算内完成就用它的结果。
2. 否则构造根行动集合：按（直接猜中、预期新增相符）排序的前 18 张 + 按近似信息量的前 8 张 + 权重最大的 8 个候选，再做等价合并；外加“使用提示”。
3. 做深度 2 的期望最大化搜索：第一步枚举所有真实反馈；第二步之后的候选只需其总权重和信息熵，就能直接查学习估值，不必真的展开集合。解出的分支使用 F̂。

加深到 3 层并没有更好（配对模拟 ΔE[S] = −0.033 ± 0.024，耗时约 10 倍），所以用 2 层；蒙特卡洛树搜索也被放弃，因为这里每个行动的反馈分布都能精确、廉价地枚举（每个行动最多约 57 种反馈），抽样只会增加方差。

耗时（原生，沿模拟活动测量 3,078 次决策）：中位数 1.7 ms、90% 8.6 ms、99% 27 ms、最坏 409 ms（精确层接近预算的少数情况）。浏览器 WASM 约为原生的 1.4 倍，开局（5,000 个候选）一次推荐约 44 ms。

## 6. 验证

**正确性**

- 规则：官方 6 个范例 + 两份真实游戏记录；与旧版判定公式在 6,740 万对卡上逐一对照，零差异。
- 卡库：从上游数据源重建，与旧版数据 8,210 组逐字段比较，零差异；重建结果逐字节可复现。
- 搜索：随机小卡池上的暴力参考解；上界可采纳性检查；等价合并的逐卡检查；深度足够时搜索等于最优解。
- 数值：比较使用容差，但排序一律用精确的全序（Rust 的排序在非全序比较器下会直接出错，这个问题在开发中实际遇到过）。

**策略质量**：与旧版算法的原生移植在完全相同的随机活动（相同目标卡、相同提示结果）上配对比较，每种设置 2,000 次：

| 活动设置 | 旧版 平均解题 / 全部通关 | 新版 平均解题 / 全部通关 | 配对差（95%） |
|---|---|---|---|
| 9／11／36 | 8.984 / 98.45% | **8.998 / 99.80%** | 通关率 +1.35 ± 0.54 个百分点 |
| 9／11／28 | 8.559 / 63.8% | **8.839 / 85.2%** | 通关率 +21.4 ± 2.1 |
| 9／4／30 | 7.358 / 14.4% | **7.761 / 22.6%** | 平均解题 +0.40 ± 0.04 |

只换价值表、不用学习估值时几乎没有提升；只用学习估值、仍用旧的固定换算比例时反而变差（会过度使用提示）。两者组合才有效。

## 7. 局限

- F̂ 和学习估值都是“某个具体策略”的价值估计，不是最优性证明；因此只有最后一题的精确层会标“已证明最优”。
- 所有结论都依赖[规则与假设](规则与假设.md)中的模型；卡池、规则开关或活动设置变化后，表需要重新拟合（`npm run fit`，约 6 分钟）。表的文件头记录了网格大小。
- 活动可能排除个别卡，这会让先验略有偏差。
- 默认活动下全部通关率已接近 100%，剩余差距主要体现在次数紧张的情况。

## 8. 重新拟合

```sh
npm run fit                  # 拟合 F̂ 和学习估值并打包 tables/tables.bin
cargo run --release -p decoder-cli -- compare data/generated/cards.bin policies=L,FV preset=9/11/28 n=2000
cargo run --release -p decoder-cli -- bench-decide data/generated/cards.bin policy=FV n=80
```

`compare` 在公共随机数上做配对比较（L＝旧版移植，F＝仅价值表，FV＝新版）；`bench-decide` 测量每一步决策的耗时分布。
