# 卡片解码者 · 求解器

《游戏王 MASTER DUEL》“卡片解码者”活动的推荐、记录与模拟工具。录入游戏里揭示的线索和每次挑战的判定，工具会实时缩小候选卡，并告诉你下一步该**先用提示**还是**挑战哪张卡**。

求解引擎用 Rust 编写并编译为 WebAssembly，在浏览器后台线程运行：推荐通常几十毫秒内给出，页面不会卡顿。

> 本项目是非官方的研究与辅助工具，与科乐美无关。它不能消除目标卡和提示字段本身的随机性。

## 主要功能

- 按边框、属性、等级／阶级／连接、种族、攻击力、守备力六项线索实时筛选候选卡
- 统一比较“先用提示”和“挑战某张卡”，给出推荐行动、本题解出概率、本次直接猜中概率和预计本活动解题数
- 最后一题候选较少时给出**精确最优解**，并明确标注哪些推荐是精确的、哪些是近似的
- 按官方规则规划次数：当前可用的次数加上之后每天还会发放的次数
- **活动轨迹**按游戏内「记录」画面的样式展示每一题的每一步
- 测试模式（公开目标卡）、小游戏模式（隐藏目标卡）
- 规模测试：用与推荐相同的策略在后台多线程模拟完整活动
- 录入矛盾时自动指出最可能录错的一条
- 导出／导入进度，可导入旧版工具的存档
- 深色／浅色界面，手机可用

## 在线使用

部署后的网址：`https://<项目名>.pages.dev`（部署方法见[部署到 Cloudflare](#部署到-cloudflare)）。

需要支持 WebAssembly 的较新浏览器；目前已在 Chrome／Edge（Chromium 内核）中测试，Firefox 和 Safari 尚待验证。所有计算都在你的浏览器里完成，进度只保存在本机，不会上传。

## 离线使用

1. 下载网站压缩包 `md-card-decoder-site.zip`（在 GitHub Releases 或 CI 产物中；也可以自己运行 `npm run pack` 生成）。
2. 解压到任意文件夹。
3. 双击 `index.html` 即可使用，不需要联网，也不需要安装任何东西。

在线和离线使用各自保存进度（浏览器把两者视为不同的网站）。需要换用时，先在一边“导出”，再到另一边“导入”。

## 使用流程

### 每一题

1. **录入初始揭示**：每题开始时游戏会免费揭示一项。在“录入揭示”里选择字段和值，来源选“初始揭示”，点“加入线索”。
2. **看推荐**：右侧“推荐行动”会自动计算。
   - 推荐**挑战某张卡**：点卡名，它会被选为本次挑战卡。
   - 推荐**先用提示**：在游戏中使用提示，然后回到“录入揭示”，来源选“提示”，录入游戏揭示的字段和值。
3. **在游戏中挑战**后，点“使用这张卡挑战”，在弹窗中勾选游戏显示为相符（黄色）的项目。边框或等级相符时，再选择游戏揭示的完整值（例如「融合／灵摆」、等级「12」）。弹窗会提示录入后还剩多少候选；如果与之前的记录矛盾，也会提醒你再核对一次。
4. 重复第 2、3 步，直到六项全部相符，然后点“进入下一题”。

也可以在“记录挑战”里直接搜索卡名（支持中文、英文、日文和常见别名）。同一题中重复判定同一张卡不消耗挑战次数，也得不到新信息，工具会提示这一点。

### 次数与天数

顶栏的“提示”“挑战”填写**游戏里当前可用**的次数；“已领取”填写已经领到几天的次数。官方规则是首日 4 次挑战、3 次提示，之后每天 13:00 再发 4 次挑战、1 次提示，未用完的次数一直累积到活动结束。工具会自动按日期估算“已领取”天数，也可以手动修改。

“计划总量”是求解器实际使用的数量：当前可用 + 之后还会发放。因为等待不会有任何损失，按计划总量规划才是正确的；当天次数用完时，等第二天 13:00 再继续即可。

### 推荐卡与游戏内筛选

游戏内的卡片列表会按已知条件自动筛选，但可以**重置筛选**后选择不符合已知条件的卡。这类卡往往能提供更多信息，所以工具会推荐它们，并在推荐下方注明“需在游戏内重置筛选”。如果不想这样操作，可以在“活动设置”中勾选“只推荐符合已知条件的卡”（推荐会略弱）。

### 活动轨迹

下方的“活动轨迹”按游戏内「记录」画面排列：Q1、Q2……每题一个标签页；左侧是目标卡（解出后显示）和已知的六项；右侧每一步一列，灯泡表示揭示（初始或提示），卡图表示挑战，黄色表示相符，✓ 表示解出。每步下方的小字是这一步之后剩余的候选数，★ 表示这一步按推荐进行。

### 测试模式与小游戏

- **测试模式**：随机抽取并公开一张目标卡，自动判定挑战，方便体验推荐的效果。
- **小游戏模式**：目标卡隐藏，自己推理；可以随时“放弃并揭晓”。

两种模式都不影响真实活动进度，点“退出模式”即可回到真实活动。

### 规模测试

按当前活动设置，用与推荐完全相同的策略模拟完整活动：平均解题数（含置信区间）、全部通关率（Wilson 区间）、平均使用的提示和挑战次数，以及解题数分布。模拟在多个后台线程中运行，随时可以停止；相同的随机种子得到相同的结果。

## 推荐怎么看

| 标签 | 含义 |
|---|---|
| **已证明最优（模型内）** | 最后一题的精确最优解：在已知规则和卡池下，不存在期望更好的策略。 |
| **题内精确 · 跨题估计** | 本题之内是精确求解；之后几题的价值来自离线模拟拟合的估值表。 |
| **近似最优（学习估值 · 深度2）** | 两步前瞻搜索；更远的步骤由离线拟合的估值模型估算。候选较多时使用。 |

- **本题解出概率**：按当前资源，最终解出本题的估计概率（模拟估计）。
- **本次直接猜中**：这一次挑战就六项全中的概率。
- **预计本活动解题**：已解出的题数加上从现在起的期望解题数。
- **提示与挑战的比较**：同时给出“先用提示”和“最佳挑战”的差距，单位是预期解题数。
- **备选**：列出其他好的选择和它们的猜中率、平均新增相符项、信息量（bit）。多个行动同样最优时，会提示“任选其一”。

推荐的目标按优先级依次是：预期解题数最多，其次首次相符项最多，最后行动次数最少。

## 活动规则与模型假设

工具使用的判定规则与游戏一致，已用官方说明中的 6 个范例和真实游戏记录验证：

- 灵摆卡的边框只要符合其中一种就算相符，并揭示目标卡的完整边框（猜测卡是灵摆时也一样）。
- 等级、阶级、连接按同一个数字比较；“规则上等级与卡图不同”的卡，规则等级和卡图等级都算，揭示的是规则等级。
- 属性、种族、攻击力、守备力按数值相等比较。

仍未确认的两点（可在“活动设置”中切换，默认按“相符”处理）：两张**不同的** “?” 攻击／守备卡是否算相符；两张不同的连接怪兽的守备力是否算相符。

完整规则、范例和模型假设见 [`docs/规则与假设.md`](docs/规则与假设.md)。

**卡池**：默认使用大师决斗游戏内卡片（YgoMaster 游戏卡表 + 百鸽数据），共 9,059 张怪兽、8,023 个判定组（六项完全相同的卡合并为一组，按张数加权）。活动可能另外排除少量卡，若某个候选确定不会出现，请忽略它。候选归零时可临时切换到“完整官方怪兽”排查。

## 进度保存与迁移

- 进度自动保存在浏览器本地（卡片按卡片密码保存，更新卡库不会错位）。
- **导出**：保存为 JSON 文件；**导入**：读取 JSON 文件，也支持旧版工具（v4）的存档文件。
- 在同一个浏览器里第一次打开新版时，如果找到旧版存档，会自动导入当前题的进度。
- “撤销”可以撤回最近的操作；“重置本题”会退回本题消耗的次数。

## 开发（Linux）

需要：Rust（rustup，stable）、Node.js 22 及以上。

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.129 --locked --root .tools   # 必须与 Cargo.lock 中的版本一致
npm ci
npm run doctor      # 检查工具链

npm run build       # 编译 WASM 并生成网站到 public/
npm run dev         # 本地预览 http://localhost:8787（WSL2 下 Windows 浏览器可直接打开）
npm test            # Rust 测试 + Node 测试
npm run test:e2e    # 浏览器端到端测试（需先 npx playwright install chromium-headless-shell）
npm run pack        # 生成上传用压缩包 build/md-card-decoder-site.zip
```

目录结构：

```text
crates/decoder-core/   求解引擎（纯 Rust：卡库、规则、候选追踪、搜索、模拟）
crates/decoder-wasm/   浏览器接口（WASM）
crates/decoder-cli/    命令行工具 mdcd：数据构建、基准测试、模拟、估值表拟合
web/                   网页源码（原生 JS 模块，打包为单个脚本）
data/                  数据源锁定文件与生成的卡库（data/generated/ 已提交）
tables/                离线拟合的估值表
tests/                 规则范例、Node 测试、浏览器端到端测试
tools/                 构建、打包、数据下载、缩略图工具（Node）
legacy/                旧版工具（冻结保存，仅用于规则对照和旧存档导入）
docs/                  规则、算法说明、重构计划的研究资料
PLAN.md                重构计划与进度记录
```

`legacy/` 里的旧版 `.cmd` 启动器和 Node 脚本已被下面的 npm 命令取代，不再维护。

## 数据更新

```sh
npm run data:update   # 下载最新的百鸽卡库与 YgoMaster 卡表，重建 data/generated/
npm run data:check    # 与旧版数据和旧版判定公式逐项对照
npm run fit           # 卡库变化后重新拟合估值表（20 线程约 6 分钟）
npm run images        # 下载新卡的缩略图并重新打包（已有的缩略图会缓存）
```

- 数据源及其哈希记录在 `data/sources.lock.json`；`node tools/data-fetch.mjs`（不带参数）会严格按锁定版本校验。
- 生成的卡库不含时间戳，同样的数据源重建结果逐字节相同。
- 构建时会检查各项不变量（字段取值范围、连接怪兽无守备、判定组唯一等）。
- 下载脚本使用 Node 自带的网络功能；若手动用 curl，请注意 anaconda 自带的 curl 证书配置有问题，改用 `/usr/bin/curl`。

## 部署到 Cloudflare

整个网站是静态文件，全部计算在访客浏览器里完成，不需要任何服务器代码，也不需要命令行。

**第一次部署**

1. 在本机运行 `npm run pack`，得到 `build/md-card-decoder-site.zip`（约 144 个文件、68 MB；也可以直接使用 `public/` 文件夹）。
2. 登录 Cloudflare 控制台，进入 **Workers & Pages** → **Create application** → **Get started** → **Drag and drop your files**。
3. 填写项目名（它会成为网址 `<项目名>.pages.dev`，以后改名等于换网址），把压缩包或 `public/` 文件夹拖进去，点 **Deploy site**。

**更新网站**

在项目页面选择 **Create a new deployment**，上传新的压缩包，选择部署到生产环境。旧版本会保留，可以随时回滚。

**说明**

- 控制台拖放上传最多 1,000 个文件、每个文件不超过 25 MiB；构建脚本会自动检查（本站约 144 个文件）。卡图因此打包成了 129 张拼图。
- `_headers`（长期缓存带哈希的文件）和 `404.html` 会一并上传；即使不生效，网站也能正常使用，每次重新部署都会立即生效。
- 只想临时预览时，也可以把压缩包拖到 [Cloudflare Drop](https://developers.cloudflare.com/changelog/post/2026-07-08-cloudflare-drag-and-drop/)，得到一个 60 分钟有效的临时网址。
- 仓库里的 GitHub Actions（`.github/workflows/ci.yml`）会自动测试并生成同样的压缩包，推送 `v*` 标签时附加到 Release；它不需要任何 Cloudflare 凭据。

## 算法说明

简要来说：

1. **候选追踪是精确的**：每条线索都是目标卡的确定函数，因此候选集合按张数加权就是准确的后验分布。
2. **跨题价值表**：每题都从同样的先验开始，所以整个活动的价值可以精确分解为一张表 F̂[剩余题数][提示][挑战]，它通过大量模拟离线拟合。
3. **学习估值**：离线统计“当前候选的信息熵 → 本题还需要多少次挑战和提示”的分布，再与价值表组合，用来估计搜索深度以外的价值。提示和挑战的取舍因此来自数据，而不是固定的换算比例。
4. **在线决策**：候选较多时做两步前瞻搜索；最后一题候选较少时用带剪枝的精确求解（给出“已证明最优”）；其他题候选很少时在题内精确求解。
5. **结果**：与旧版算法在相同随机活动上的配对模拟（每种设置 2,000 次）：

| 活动设置（题数／提示／挑战） | 旧版全部通关率 | 新版全部通关率 |
|---|---|---|
| 9／11／36（本期活动） | 98.45% | **99.80%** |
| 9／11／28 | 63.8% | **85.2%** |
| 9／4／30 | 14.4% | **22.6%** |

详细说明见 [`docs/算法说明.md`](docs/算法说明.md)；重构的完整计划、决策与研究记录见 [`PLAN.md`](PLAN.md) 和 [`docs/plan/research/`](docs/plan/research/)。旧版的模型文档保存在 [`docs/legacy/`](docs/legacy/)。
